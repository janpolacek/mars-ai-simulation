# Project documentation

Use this skill for repository Markdown that explains Red Horizon operations,
architecture, lore governance, technical decisions, or repeatable workflows. For
Word/PDF artifact production, use the environment's document/PDF skills instead.

Read the relevant existing document first. Keep documents specific enough for a
new agent to act without inventing policy, but avoid turning Markdown into a task
backlog: durable work belongs on the Hermes kanban board. Maintain the boundary
that private timeline information is never public-site content. Link canonical
documents rather than duplicating rules, and update navigation when adding a
document.

Validate links, terminology, and contradictions against `docs/GENERAL.md` and
`docs/INSTRUCTIONS.md`. Record any non-editorial conflict for human resolution.
